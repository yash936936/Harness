# Component: memory

> Area type: bundle. Location: `src/bundles/memory/`. Hand-written sections describe the service and its invariants; the files-and-exports block is generated by `npm run docs:components`.

## Purpose

Composes the episodic and hot memory tiers behind `ctx.memory`. It records one log-linked episode per agent turn, provides actor-scoped read views, injects the hot tier into agent prompts, and runs deterministic lesson compaction. The optional semantic tier is a separate service and is attached only when embedding and vector-store dependencies are configured.

## Route (how control reaches it)

`profile-coding` installs `Memory` after `log`, `egress`, and `agentLoop`. The service is registered as `ctx.memory`; it composes `EpisodicMemory`, `HotTier`, `MemoryAccess`, and `Compaction`. `runTurn` delegates to `ctx.agentLoop.run`, then records the turn's session-log sequence range as an episode. When configured, `MemorySemantic` is installed separately and attached through `ctx.memory.setSemanticService`. Sub-agent reads use `ctx.memory.view(actor)` and require a live grant.

## Config surface and invariants

- `path` selects persistent episodic and hot-tier storage. Without it, memory remains in process.
- `maxFieldChars` bounds stored episode fields; `hotTokenCap` bounds the rendered hot tier.
- `maxPendingEpisodeWrites` bounds outstanding writes to persistent episodic storage, including the active write. It defaults to 1024 and must be a positive safe integer.
- `MemorySemantic` accepts `maxPendingOperations` to bound serialized semantic mutations and reads per service instance. It defaults to 256 outstanding operations and is hard-capped at 4096.
- `MemorySemantic` accepts `reindexBatchSize` to bound facts embedded and vector-upserted per reindex batch. It defaults to 64 and is hard-capped at 1000.
- Persistent and in-memory semantic stores enforce an active searchable-fact quota (`maxFacts`, default 10000) and a serialized per-fact byte cap (`maxFactBytes`, default 8192). At the active-fact cap, new IDs are rejected; replacing an existing ID remains allowed. These quotas never auto-delete durable history.
- Persistent semantic facts use append-only `semantic.events.jsonl` plus rebuildable `semantic.index.jsonl` and `semantic.index.meta.json`. A validated legacy `semantic.json` array is imported once and retained unchanged as a backup. ID lookup, text deduplication, and semantic query hit hydration use indexed byte ranges. The disposable sidecar is compacted to live facts after rebuild and when its size exceeds `max(64 KiB, activeFactCount × 256 bytes)`, so repeated replacements/deletions do not make warm-start metadata proportional to event history. The authoritative event log is never compacted or deleted.
- `deriveLessons` defaults to false. When enabled, lessons are templated only from harness facts in the session log, never model or file text.
- `injectHot` defaults to true. The hot tier is added as a system section at order 10.
- `compaction.everyTurns`, when set, must be a positive safe integer. Compaction errors are recorded in `lastCompaction` and do not fail the user's turn.
- Episodic writes are idempotent by `sessionId:fromSeq`; records are linked to their source log sequence range and registered secrets are redacted before storage and return.
- Persistent episodic storage keeps `episodic.jsonl` authoritative and maintains a rebuildable `episodic.index.jsonl` identity sidecar plus a size manifest. Duplicate detection and `findById` use the sidecar during normal operation; missing, malformed, or size-stale index data is rebuilt under the episode file lock. The index can be deleted safely because it is a projection, not source data. The sidecar also stores query metadata; warm paginated reads select matching index entries and read only page-sized source ranges. A missing, corrupt, or stale index still requires one full source-log rebuild.
- Scoped actors with no live memory grant fail closed. Their episode queries are forced to their own actor ID.
- `MemoryAccess.grant` accepts only `subagent:<id>` actors with a 1-64 character `[A-Za-z0-9_-]` identifier. Malformed actor names cannot be granted memory visibility.

## Known limits

- Episodic memory is a record of turns, not evidence that a real model learns from it.
- The persistent episode write queue limit is per process and per store instance. It does not coordinate queue capacity across processes.
- Rebuilding a stale episodic identity index requires one full pass over the authoritative JSONL log and an in-memory ID map. Cursor pagination uses the persistent metadata index for warm reads. It scans the in-memory metadata map but reads only the selected page records from the authoritative log; the cold index rebuild is the only full-history source scan.
- The semantic tier is optional and depends on embeddings plus a vector store. Its presence does not prove live retrieval quality.
- The token estimate defaults to `ceil(chars / 3)`; there is no tokenizer in this project.
- Compaction uses deterministic templates and configured thresholds, not a model-generated summary.
- The persistent compaction ledger rejects symlinked parent/final paths and uses exclusive, unique temporary files for atomic replacement.
- Semantic fact mutations and vector-index writes share a serialized lock. A delayed embedding cannot overwrite a newer same-ID fact, and a removal cannot delete a replacement's vector.
- The semantic operation queue limit is per process and per service instance; it does not coordinate capacity across processes.
- The semantic `list()` API still materializes every fact for compatibility. Persistent reindex reads bounded pages and stores a source-version/model-fingerprint checkpoint in `semantic.reindex.checkpoint.json`; vector upserts are idempotent, so a crash before checkpoint advancement safely repeats the last batch. A source change invalidates the checkpoint and returns a retryable error. Public semantic pagination is available through `ctx.memorySemantic.page({ limit, cursor })`. The active semantic index is held in a bounded ID/text map under the configurable fact quota; append-only event history is retained indefinitely by default. Page limits are 1-1000 items (default 50). The opaque cursor is tied to the source revision; writes or removals between pages invalidate it with a stale-cursor error. `list()` remains available when callers intentionally need every fact.
