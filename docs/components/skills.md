# Component: skills

> Area type: bundle. Location: `src/bundles/skills/`. Hand-written sections describe the service and its invariants; the files-and-exports block is generated by `npm run docs:components`.

## Purpose

Discovers and validates Agent Skills from explicitly configured directories, then exposes them through progressive disclosure. The index lists skill names and descriptions, `load_skill` returns the instruction body, and `read_skill_resource` reads one bundled file. Skills are read as data; this component does not execute their scripts.

The keyword and embedding matchers live in `matching.ts`. They select relevant skills for optional host-side auto-loading and do not own directory scanning, parsing, tool registration, or resource reads.

## Route (how control reaches it)

`profile-coding` installs `Skills` when a skill configuration is supplied. The service registers `load_skill` and `read_skill_resource`, and optionally adds `skills.index` and `skills.auto` system sections to `ctx.agentLoop`. The host can call `load()`, `reload()`, `list()`, or `renderIndex()` through `ctx.skills`. The exported `keywordMatcher` and `embeddingMatcher` factories are supplied as `autoLoad.matcher`.

## Config surface and invariants

- `dirs` is required and non-empty; there is no implicit default skill directory.
- `index` defaults to true. `autoLoad` is optional and requires a matcher function; its `max` value, when supplied, must be a positive integer.
- Index and instruction token budgets and resource character limits are positive integers. The defaults are 2,000 index tokens, 5,000 instruction tokens, and 20,000 resource characters.
- Skill names must be 1-64 lowercase letters/digits separated by single hyphens and must match their containing folder.
- Resources must resolve inside the skill directory. Hidden files, `SKILL.md` siblings, binary files, symlink escapes, and oversized instruction files are refused or bounded.
- Instructions and resources are redacted through egress before being returned to the model.

## Known limits

- The keyword matcher uses distinct content-word overlap, with no stemming or synonym expansion.
- The embedding matcher requires an explicit model-specific `minScore`; the documented example score is not a universal threshold.
- Auto-load is best-effort. Matcher or embedding failures are recorded in `lastAutoLoad.error` and do not fail the agent run.
- A listed skill or bundled script is not an authorization to execute it. Execution remains subject to sandbox and policy gates.
